# Deploying Fuel the Ride

Production = **Render** (one Docker web service: API + built web app) + **MongoDB Atlas** (managed database), both in **US West (Oregon)**.

```
GitHub (merge to main) → CI: tests + Docker/Postman → deploy hook → Render builds the Dockerfile → https://<app>.onrender.com
                                                                                               ↕
                                                                                MongoDB Atlas (AWS us-west-2)
```

Render's own auto-deploy is **off** (`render.yaml`). Only CI deploys, and only after every test passes on `main`.

## One-time setup (≈ 20 min)

### 1. MongoDB Atlas (database)
1. Sign up at https://www.mongodb.com/cloud/atlas and create a **free M0 cluster**: provider **AWS**, region **Oregon (us-west-2)**.
2. **Database Access** → Add a database user, e.g. `fuel-ride-app`, with an autogenerated password. Role: **Read and write to any database**.
3. **Network Access** → Add IP address → **Allow access from anywhere** (`0.0.0.0/0`). Render's free plan has no fixed IP. The database is still protected by the user/password and TLS.
4. **Connect** → **Drivers** → copy the connection string. Replace `<password>` with the user's password, and add the database name **`fuel_ride`** before the `?`:
   ```
   mongodb+srv://fuel-ride-app:<password>@cluster0.xxxxx.mongodb.net/fuel_ride?retryWrites=true&w=majority
   ```
   Keep it private: it's the key to your data.

### 2. Render (app server)
1. Sign up at https://render.com with your GitHub account.
2. **New** → **Blueprint** → choose the `fuel-the-ride` repo. Render reads `render.yaml` and proposes the **fuel-the-ride** web service.
3. Fill in the values it asks for:
   - `MONGODB_URI`: the Atlas connection string from step 1.4.
   - `GOOGLE_CLIENT_ID`: leave empty for now (the Google button stays hidden).

   `JWT_SECRET` and `JWT_REFRESH_SECRET` are generated by Render automatically.
4. **Apply**. The first build takes ~5 minutes. Your app's address appears at the top, e.g. `https://fuel-the-ride.onrender.com`.
5. Check it: open `https://<your-app>.onrender.com/api/health`. It should show `"db":"up"`.

### 3. Connect GitHub → Render (deploy after tests pass)
1. Render → your service → **Settings** → **Deploy Hook** → copy the URL. It's secret: anyone with it can trigger deploys.
2. GitHub repo → **Settings** → **Secrets and variables** → **Actions**:
   - **Secrets** tab → New repository secret: `RENDER_DEPLOY_HOOK_URL` = the hook URL.
   - **Variables** tab → New repository variable: `APP_URL` = `https://<your-app>.onrender.com` (no trailing slash).

   You can do the same from a terminal with `gh secret set RENDER_DEPLOY_HOOK_URL` (it asks for the value without showing it) and `gh variable set APP_URL --body https://<your-app>.onrender.com`.

From now on, every merge to `main`:
1. runs the tests and the Docker + Postman checks
2. triggers the Render deploy
3. waits until `/api/health` reports the new commit with the database up. The **Deploy to Render** check goes green only then.

## Things to know
- **Free plan sleeps** after ~15 minutes without visits. The first visit then takes ~30–60 s to wake up. Render's **Starter** plan keeps it always on.
- **HTTPS** is automatic. Chrome on your phone works, and the login cookies are `Secure`.
- **Logs:** Render → your service → **Logs**. **Database:** Atlas → **Browse Collections**.
- **Backups:** the Atlas free tier has no automated backups. Before real users, move to a paid tier with backups, or export regularly with `mongodump`.
- **Rolling back:** Render → **Events** → pick an earlier deploy → **Rollback**. Or revert the commit on GitHub and let CI deploy again.
- **Google sign-in later:** create the OAuth client (see PRODUCT.md "Before launch"), add `https://<your-app>.onrender.com` as an authorized JavaScript origin, and set `GOOGLE_CLIENT_ID` in Render → Environment.
